# 16 · Asset ที่ผู้ใช้นำเข้าเอง

> ผู้ใช้อัปโหลดภาพของตัวเอง (โลโก้ช่อง ภาพที่ถ่ายเอง ภาพที่ซื้อ license มา) ในหน้า **Asset list → Asset ของคุณ** ของ HistoryTeller หรือด้วย `node scripts/import-asset.mjs add …`
> **ก่อนทำ stage 5 (Shot list) และ stage 6 (Asset list) ทุกครั้ง: รัน `node scripts/import-asset.mjs list <slug>`** แล้วพิจารณาใช้ภาพที่ตรงกับเนื้อหาก่อนวาดใหม่หรือสร้างภาพ AI

## เก็บที่ไหน
| ขอบเขต | ข้อมูล | ไฟล์ภาพ |
|---|---|---|
| เฉพาะโปรเจกต์ | `projects/<slug>/imports.json` | `public/<slug>/user/<id>.<ext>` |
| คลังกลาง (ทุกโปรเจกต์) | `library/library.json` | `public/_library/<id>.<ext>` |
ทั้งสองที่ไม่ขึ้น git (ภาพส่วนตัวของผู้ใช้) · id ซ้ำ = โปรเจกต์ชนะคลัง

## ข้อมูลแต่ละชิ้น
| ช่อง | ใช้ทำอะไร |
|---|---|
| `id` | รหัสที่ใช้ในช็อต: `user:<id>` |
| `description` | **ภาพนี้คืออะไร ควรใช้ตอนไหน** — Claude ใช้ตัดสินว่าวางช็อตไหน (บังคับ) |
| `kind` | `photo` ภาพถ่าย/เอกสาร (ติดกระดาษ ขอบขาว + เงา) · `cutout` PNG พื้นโปร่งใส (วางลอย) · `plate` ฉากหลังเต็มจอ (`cover: true`) · `logo` แสดงตามจริง ไม่ใส่ filter |
| `owner` | ที่มา/สิทธิ์ใช้งาน (บังคับ) — เช่น "ถ่ายเอง", "โลโก้ของช่อง" |
| `credit` | ถ้ามี จะขึ้นบรรทัด "ที่มา" มุมจอ และหัวข้อ "ภาพประกอบ" ท้ายโพสต์ให้เอง |
| `tags` · `era` | ช่วยค้น · ยุคที่เข้ากับภาพ |

## ใช้ในช็อต
```json
{"id": "photo", "asset": "user:chedi-morning|chedi-bell", "style": "collage", "z": 1000, "x": 0, "y": -40, "w": 640, "rot": -2}
{"id": "logo",  "asset": "user:channel-logo", "style": "vector", "z": 500, "x": 380, "y": -760, "w": 160}
{"id": "bg",    "asset": "user:my-landscape|sky", "style": "vector", "z": 3600, "cover": true}
```
- ใส่ vector สำรองหลัง `|` เสมอเมื่อเป็นไปได้ (ถ้าผู้ใช้ลบภาพ วิดีโอยังไม่พัง) · ไม่มีสำรองแล้วภาพหาย → validate เป็น error
- เคารพคำอธิบาย: ถ้าผู้ใช้เขียนว่า "ใช้ตอนเปิดคลิป" ให้ใช้ตรงนั้น · ภาพที่ไม่เข้ากับเนื้อหาไม่ต้องฝืนใช้
- ขนาดบนจอ: ภาพ < 1,000px อย่าให้กว้างเกิน ~60% ของเฟรม หรือโดนกล้องซูมเข้า (จะแตก) · plate ต้องกว้าง ≥ ความกว้างเฟรม
- ภาพที่มีบุคคล: ใช้ได้เพราะผู้ใช้ยืนยันสิทธิ์แล้ว แต่ข้อห้ามใน brief (เช่น ห้ามใบหน้าบุคคลศักดิ์สิทธิ์) ยังชนะ
- บันทึกใน `assets.md` หมวด "Asset ของผู้ใช้" (id · ใช้ในช็อต · ที่มา)

## เมื่อมี asset ใหม่เข้ามา (หลังเริ่มงานแล้ว)
ผู้ใช้เลือกตอนนำเข้า (หรือปุ่มบนการ์ด) ว่าจะใช้แบบไหน:
| แบบ | ทำอะไร | ใครทำ | กระทบ |
|---|---|---|---|
| **ก. ใช้แทนของเดิม** | `projects/<slug>/asset-map.json` → `{"map": {"chedi-bell": "user:my-chedi"}}` (หรือ `{"to": "…", "keepAnimated": true}` = ช็อตที่ของเดิมมี props ขยับยังใช้ของเดิม) · render/stills/cover/validate แทนให้ทุก layer + เก็บ vector เดิมเป็นสำรอง | ผู้ใช้กดในหน้า Asset list / Shot list (ระบบแสดงผลกระทบก่อนยืนยัน) | **shots.json ไม่เปลี่ยน** · Preview/Render · QA · (ปก ถ้าใช้) ล้าสมัย |
| **ข. ใส่เพิ่มในช็อต** | feedback `user:<id>` เข้าคิว Claude | Claude (ข้อด้านล่าง) | Shot list กลับเป็น review · Render/QA ล้าสมัย |
| **ค. ต้องมีช็อต/แก้บท** | ผู้ใช้ต้องสั่งชัดเจนเท่านั้น | Claude | ถ้าแก้บท → เสียงพากย์ซีนนั้นต้องสร้างใหม่ |

**Claude เมื่อได้ feedback `user:<id>` (หรือ `ref:<id>` แบบใส่เพิ่ม):**
1. อ่าน `description` + ข้อความใน feedback → เลือกช็อตที่ภาพตรงกับสิ่งที่เสียงพูด *ในวินาทีนั้น* (หลักใหญ่ข้อ 2)
2. ใส่เป็น layer ใหม่หรือแทน layer เดิม **พร้อม vector สำรองหลัง `|` เสมอ** · ขนาด/ตำแหน่งตาม safe zone (rule 02) · ไม่บังตัวหนังสือหรือซับ
3. **ห้ามแก้ `vo` / `voTTS` / `voEn`** เว้นแต่ผู้ใช้สั่ง — เวลาของวิดีโอมาจากเสียงพากย์ ไม่แตะบท = ไม่ต้องสร้างเสียงใหม่
4. ถ้าแค่ "แทนของเดิมทุกช็อต" ตรงกับที่ผู้ใช้ต้องการ → แนะนำให้ใช้แบบ ก (ปุ่ม "ใช้แทน…") แทนการแก้ shots.json
5. รัน `node scripts/validate.mjs projects/<slug>` → ปิด feedback พร้อม note "ใส่ใน S02-03, S05-01 · render ใหม่" · ตั้ง stage `shots` เป็น `review` · อัปเดต `assets.md`
- ภาพที่ยังไม่ได้ใช้: validate เตือน "asset ที่นำเข้ายังไม่ได้ใช้" — ตอนทำ stage 5/6 ให้พิจารณาทุกชิ้น ถ้าไม่ใช้ให้เขียนเหตุผลใน assets.md
- ความล้าสมัย: Preview/Render · QA · ปก เก็บลายนิ้วมือของภาพที่ใช้จริงตอนอนุมัติ → เลือกรูป AI ใหม่ / อนุมัติภาพจริง / นำเข้าไฟล์ทับ / แก้ asset-map หลังอนุมัติ = ขึ้น "ล้าสมัย — ภาพที่ใช้เปลี่ยน"

## ห้าม
- Claude **ห้ามนำเข้า/ลบ/แก้ภาพของผู้ใช้เอง** โดยไม่ได้รับคำสั่ง (แก้ `description` ได้เมื่อผู้ใช้ขอ) · ห้ามแก้ `asset-map.json` เอง (ผู้ใช้ยืนยันผลกระทบในหน้าเว็บ)
- ห้ามนำภาพจากเว็บมาใส่เป็น asset นำเข้าแทนการตรวจ license — ภาพจากแหล่งภายนอกต้องผ่าน `refs.json` (rule 15)
